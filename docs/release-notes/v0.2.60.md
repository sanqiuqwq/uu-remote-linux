GNOME 会话被 RDP 强制结束并重建后，主机使用新会话的显示环境重新初始化 Portal。/ Re-adopt the display of the new GNOME session after an RDP Force Stop.

### 变更 / Changed
- **强制结束本地会话后重新取环境**：`PartOf=graphical-session.target` 仍会让主机随旧会话退出；新会话启动时 systemd user manager 可能仍保留旧会话的 `WAYLAND_DISPLAY`。主机在枚举后端之前用 `loginctl show-user -p Display` 解析当前活动会话，确认 socket 存在后再导出 `WAYLAND_DISPLAY` / `DISPLAY` / `XDG_SESSION_TYPE`，最多等待 15 秒；socket 有效或 X11 会话时不做任何改动。/ Before backend selection the host resolves the live display through `loginctl show-user -p Display` (bounded 15 s) and exports it, so a force-stopped session cannot leak a dead compositor socket into the new one. A live socket and X11 sessions are untouched.
- **Portal 会话不复用**：每次桌面连接仍新建 Portal session；旧会话被终止后进程由 systemd 重启，内存中的 session、monitor 与 restore token 不会跨会话复用；Portal 重启仍由既有 recovery 路径重建 session。/ Every desktop offer still opens a fresh portal session; the restarted process keeps no session, monitor or token in memory.
- **GNOME backend 白名单补丁（单独交付）**：`packaging/gnome-portal/gnome-50-uu-whitelist.patch` 仅对 app_id `uu-remote-linux`（且已安装 `uu-remote-linux.desktop`）自动通过 ScreenCast / RemoteDesktop 的 Start 授权，其他应用与空 app_id 仍走原对话框，并输出审计日志。该补丁不修改 UU Remote 源码，需按说明单独编译安装。/ `packaging/gnome-portal/gnome-50-uu-whitelist.patch` auto-approves ScreenCast/RemoteDesktop Start only for app_id `uu-remote-linux` with an installed desktop file; every other app id keeps the dialog and an audit line is logged.

### 已知 / Notes
- 白名单补丁需匹配 `xdg-desktop-portal-gnome` 50.0 源码；未打补丁时行为与 v0.2.59 相同（首次连接仍需人工确认）。
- 会话切换的实际效果（开机 → Force Stop → RDP 登录 → 自动出画面）需在 GNOME 50 主机上验证。
