修复 GNOME 50 / Ubuntu 26.04 下 Portal 应用身份为空导致投屏授权无法恢复的问题。/ Fix persisting screen-share consent on GNOME 50 (empty portal app_id).

### 修复 / Fixed
- **Portal 应用身份**：GNOME 50 按应用身份保存 RemoteDesktop / ScreenCast 授权。主机现在在共享 session bus 上、第一次 Portal 调用之前通过 `org.freedesktop.host.portal.Registry` 注册已安装的 `uu-remote-linux.desktop` 身份，Portal backend 不再收到空 app_id，`persist_mode=2` 的 restore token 可正常对应到本机显示器，重启服务后无需再次授权。/ The host registers the installed `uu-remote-linux.desktop` identity on its shared session bus before the first portal call, so the backend no longer sees an empty app_id and persisted `persist_mode=2` consents restore after a restart.
- **Portal 重启**：监听 `org.freedesktop.DBus.NameOwnerChanged`，Portal 服务重启后自动重新注册；按 owner 去重，不会重复刷日志，注册失败只记录并继续原有初始化与错误路径。/ Re-registers after the portal service restarts, deduplicated per owner; failures are logged and the existing initialization/error path continues.
- 既有 restore token 保存、按显示器映射的授权文件保持不动；不会在启动或升级时清空授权。

### 已知 / Notes
- 若系统没有安装 `uu-remote-linux.desktop`，注册会失败并记录错误，其余功能照旧。
- 首次授权仍需本机确认一次；成功后同一显示器的后续连接不再询问。
